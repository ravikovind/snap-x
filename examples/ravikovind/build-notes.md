# Build notes — Ravi Kovind LinkedIn cover (revision 2)

Built from [`plan.md`](plan.md) with snap-x. The plan is the source of truth for copy, layout, colour and type; this file records how it was executed and what differed.

## What changed in revision 2
- **Fonts:** Nunito Sans (all text) + Saira (the "mono role": the `//` philosophy line and the `RK` monogram). Was Inter + JetBrains Mono.
- **Palette:** the Open Notifier look — pure black, one accent — with the accent moved **green → yellow** (`#FAC800`, Open Notifier's own yellow). Green (`#10B981`) survives only as the start of the single gradient ring (green → yellow).
- **Removed as unclear:** the node-graph bridge and its `app/api/mcp` labels, the scattered accent pixels, the dot grid, the footer URL tag and the dashed outer ring. Orbit simplified from 4 rings / 6 nodes to 3 rings / 3 nodes.

## How it was built
- `designs/_cover.mjs` — the whole 1584×396 composition as one builder. The `_` prefix marks it as a helper, so `snap-x render` skips it and renders only the four entry files.
- `designs/cover.mjs` → `ravi-kovind-linkedin-cover.png` (1584×396)
- `designs/cover-2x.mjs` → `…@2x.png` (3168×792): the same vector tree with `transform: scale(2)`, equivalent to `deviceScaleFactor: 2`.
- QA views are generated by `snap-x guides` (configured in `example.json`): `guides/…guides.png` (danger zones) and `guides/…mobile.png` (the phone crop). These replaced two hand-written QA designs.

## Deviations from the plan
1. **snap-x (Satori → PNG)** rather than HTML + Playwright — this is a snap-x example.
2. **No `.jpg`** — snap-x outputs PNG only; LinkedIn accepts PNG.
3. **`★` and `●` are drawn shapes** (inline SVG star, CSS circle), not font glyphs, so they can never render as blank boxes.
4. **Saira is not a true monospace** — used for the mono role by choice (per the plan).
5. **Stats are stacked** (number over label) to keep the block within `x ≤ 1080`.
